# Amendia documentation

**Start here → [methodology/amendia_operating_model.md](methodology/amendia_operating_model.md)** — the front
door. It provides the reading order across the methodology; the folders below are organized by *kind* of
document, not by sequence (filenames are descriptive, not numbered).

For the one-paragraph pitch, see [amendia_project_brief.md](amendia_project_brief.md).

## Map

- **[methodology/](methodology/)** — the onboarding methodology a customer/implementer follows: the operating
  model (front door), process-discovery playbook, design sign-off, MCP implementor guideline, capability
  hardening & certification, the onboarding guides/runbook, UX refinements, and go-live readiness.
  - **[methodology/worked-examples/](methodology/worked-examples/)** — the wire-transfer exception worked
    example end to end: scenario walk-through, the exception reference, the process diagram, and the as-is /
    to-be BPMN.
- **[reference/](reference/)** — platform reference: the five platform contracts, the contracts and services
  references, the agent-runtime execution pipeline, and the contracts/runtime interplay diagrams.
- **[operations/](operations/)** — operating and user guides: the user guide, admin/user management, auth
  architecture, LLM configuration, the nemoclaw operator runbook, the persona map, auth diagrams, and the
  [FAQ](operations/FAQ/).
- **[engineering/](engineering/)** — internal engineering and planning notes: build plan, BPMN backlog /
  deferred backlog / conformance dossier, onboarding-wizard catch-up plan, secure-runtime plan, the
  domain-neutrality audit, and the ADR-047 D2 completion report.
- **[_build-prompts/](_build-prompts/)** — the build-time Claude Code prompts kept for provenance (not part of
  the methodology a reader follows).
- **[adr/](adr/)** — architecture decision records (numbered, chronological).
