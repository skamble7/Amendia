Amendia agent-runtime — execution modes

One engine, two substrates. The executor factory picks where a capability runs; everything else — the graph, HITL gates, artifacts, timers, audit — is shared.

Where it runsAGENTRT_EXECUTION_MODE = native (in-process) · nemoclaw (OpenShell sandbox). This diagram's two branches.
Whether it's realAGENTRT_SIMULATION_MODE = true → stubbed · false → real LLM/MCP calls.
Which modelAGENTRT_LLM_CONFIG_REF → a ConfigForge profile (provider + model, hot-swappable).

Native is byte-for-byte the pre-NemoClaw executor — capabilities run in the agent-runtime container; no sandbox, egress enforcement, credential isolation, or deep_agent. This is what you run locally today.
NeMoClaw routes execution to a capability-worker inside an OpenShell sandbox: the gateway brokers credentials (the workload never holds keys), egress is default-deny + a contract-derived allowlist, and everything is OTLP-traced. Dev Level 1 uses the deterministic Fake client; real OpenShell is Level 2.
Shared, mode-independent: the BPMN engine, HITL approval gates, typed/pinned artifacts + declared dataflow (lineage), the actor log, durable timers, and version-pinned reproducibility apply in both modes.
